# リリース品質確認（開闢 2.0.0）

最初の確認は2026-10-23、2.0.0の公開準備の確認は2026-10-24（日本時間）。対象は `claude/tauri-ui`。比較対象は `main` の `ce949e8`（Python版 1.4.1。旧アプリ）。

## 判断

**正式版 `v2.0.0` の公開を止める問題は見つかっていない。** 初回レビューのP1・P2の5件は解消し、データ移行・設定保存の失敗通知・配布物の作成まで実装した。公開前に確認していない項目は、下の「未確認」にまとめた。新規PCでの起動確認と、名称の商標確認は、公開前に行うことを勧める。

確認は次の3種類で行った。それぞれ、確認した範囲が違う。

- **自動テスト・CI**: Rust・Tauri側のテスト、clippy、fmt、Vueの型検査と本番ビルド。
- **配布zipを別フォルダへ展開した実アプリ**: 隔離した `APPDATA` で起動し、WebView2のリモートデバッグ経由で画面を操作。ウィンドウを閉じる操作は、ウィンドウに閉じる要求を送って確認した。
- **旧アプリが実際に作ったデータ**: 旧Python版を隔離した `APPDATA` で動かして作った設定・カード名・登録データで、移行を確認した。

「ビルドできる」ことを「製品として問題なく使える」ことと同一視しない。

## 解消した問題

### P1: 登録後の清掃が別の入力から保存した画像も削除した

各結果が実際に作ったファイルを `saved_paths` として保持し、`remove_review_copy` はその一覧のうち `review/`・`not_card/` 内の webp/png だけを消す。同じ名前の別形式は消さない。対象外のパスが1つでもあれば何も消さない。both形式では同じ処理が作った2ファイルだけが対象。同名・別形式の別画像が残るテストを追加した。実アプリで、別フォルダの同名入力から `not_card/shot.png` と `shot.webp` を作り、片方を登録・確定させて、もう一方が残ることを確認した。

### P1: 処理中に閉じると保存完了を待たなかった

終了時に画面が `shutdown` を呼ぶ。バックエンドは新しい処理の開始を止め、実行中の処理へ中止を伝え、処理が終わる（panicでも解除される）まで待つ。対象は画像処理、データ更新、登録時の照合データ追加、登録後の再処理。始まった画像の書き込みと `log.csv` の記録を終えてから閉じる。実アプリ（256枚、重複スキップなし）で、処理開始の約0.7秒後に閉じて、webp・bothとも約1秒で終了し、空のファイルはなく、`log.csv` の行数と保存数が一致した。カード名の取得中に閉じても、`card_names.json` と一時ファイルは残らなかった。

### P1: 新アプリのタグでも旧Pythonアプリが配布された

`.github/workflows/build.yml` を新アプリ用に置き換えた。Vueの型検査・本番ビルド、RustコアとTauri側のtest・clippy・fmt、リリースexeのビルド、配布物（zip・SHA-256・第三者ライセンス・利用案内）の作成を行い、artifactとして保存する。リリースへの添付はしない（手動）。旧PyInstallerの配布経路はなく、旧Pythonテストは基準実装の回帰テストとして残す。`tools/check_release_version.py` が、各ファイルの版が一致すること、タグが製品版と一致し、v2以降であることを確認する。

GitHub Actionsは、`v2.0.0-beta.1` のタグと、最新の `c69b114` で、すべてのジョブが成功している。

### P2: CSVを書けなくても成功として扱った

`write_csv` の失敗を `csv_error`（パスとOSのメッセージ）として終了結果に入れる。画像の件数・エラー数には混ぜない。画面は状態欄と警告に表示し、CLIは標準エラーにも出す。`log.csv` がディレクトリのとき、共有なしで開かれているときのテストを追加した。実アプリで「確定 1 / エラー 0」のまま警告が出ることを確認した。

### P2: 確認・登録後の再処理が元の設定を引き継がなかった

処理を始めたときの出力先・形式などを結果ごとに保持し、再処理と古いコピーの清掃に使う。実アプリで、出力先と形式を変えてから登録しても、元の出力先に元の形式で保存されることを確認した。画面側のこの判断にはユニットテストがない（GUIにテスト基盤がないため）。

### 設定の保存に失敗しても通知されなかった

設定を保存できなかったとき、画面にダイアログで知らせる。失敗が続く間は1回だけ表示し、処理のたびや閉じるときには繰り返さない。通知できなくても、処理と終了は止まらない。保存先を置き換えられないとき、書きかけの一時ファイルを残さない。テストを追加し、実アプリで、読み取り専用の設定ファイルのときに、通知が1回だけ出ること、閉じられない状態にならないこと、閉じるときに2回目の通知が出ないことを確認した。

### ユーザーデータの保存先と移行

保存先は `%APPDATA%\mdript-v2`。初回起動時に、旧アプリの `%APPDATA%\mdript` から設定・カード名・登録データを、読み取り専用の移行元としてコピーする（`gui/src-tauri/src/migrate.rs`）。旧アプリのフォルダは変更しないので、旧アプリへそのまま戻れる。

- コピー前に原本を `mdript-v2\legacy-backup\` に控える。書き込みは一時ファイル経由。
- JSONとして読めない、または形の違うファイルは取り込まず、画面に知らせる。設定は既知の項目だけを取り込む。
- 新アプリ側にすでにあるファイルは上書きしない。完了すると `migration.json` を残し、以後は何もしない。途中で止まったときは、次の起動で残りだけをやり直す。
- CLIの保護（旧アプリのフォルダへの書き込みの拒否）は変えていない。

**実際の旧アプリが作ったデータで確認した。** 旧Python版（`main` のコード）を隔離した `APPDATA` で動かし、公式データベースからカード名を取得（14,343件）し、`--learn` で登録データを追加し、設定を保存した。このフォルダを移行元にして新アプリを起動し、次を確認した。

- カード名・登録データがバイト単位で同一にコピーされること。設定の値が引き継がれること。
- 旧アプリのフォルダが変わらないこと（全ファイルのSHA-256が不変）。
- 移行後の起動で、旧アプリで登録した画像が「確定」になり、移行したカード名で保存されること。
- 新アプリ側にすでにあるファイルは上書きされず、足りないファイルだけが取り込まれること。

## 名称「開闢」の重複確認

調べた範囲では、競合するソフトは見つからなかった。調べたのは、Web検索（日本語・英語）と、GitHubのリポジトリ検索（「開闢」「kaibyaku」）。「開闢」という名前のWindowsアプリ・画像ツール・遊戯王関連ツールは出なかった。GitHubで見つかった「開闢」を含むものは、韓国の雑誌『開闢（개벽）』のスクレイパーと、中国語圏の個人の小さなリポジトリで、用途が違う。

- **カード名との関係**: 「開闢」を含むカード名がある（開闢の騎士、開闢なる予幻視、カオス・ソルジャー -開闢の使者-）。「開闢」だけの言葉は一般的な語で、README・画面には「株式会社KONAMIおよび遊戯王公式とは関係ありません」と書いてある。
- **確認できていないこと**: 特許情報プラットフォーム（J-PlatPat）の商標、Microsoft Store、Steamなどの直接の検索は、この環境では行えなかった。名称の確認は、これらの結果を足すまで完了とは言えない。公開前に、J-PlatPatで「開闢」の商標（第9類・第42類）を確認することを勧める。

## 未確認

- **新規PC**: 開発環境のないPCでの起動、WebView2未導入の環境、通常ユーザー権限、日本語・空白を含むパスでの確認は、この環境では行えていない。日本語・空白を含むフォルダへ展開したzipでの起動は確認した。
- **実際の撮影画像**: 実ウィンドウモード、1280x720〜4Kの実撮影、実際の「要確認」画像での登録は未確認。登録後の再処理は、加工した画像で確認した。解像度は、2560x1440の256枚を縮小した画像で確認した（[対応解像度の検討](resolutions-and-extensibility-2026-10-24.md)）。
- **ファイルのロック**: Excelで開いた `log.csv` は、共有なしで開いたファイルで再現した。実際のExcelでは未確認。
- **性能**: 起動時間・メモリは未計測。
- **コード署名**: exeに署名がない。SmartScreenの警告が出る場合がある。案内に明記している。
- **GUIの自動テスト**: ない。画面の確認は、実アプリを操作するスクリプトで行った（リポジトリには入っていない）。
- **CIが作ったexeの確認**: 以下の検証は、ローカルでビルドした配布zipで行った。公開するzipは、タグのCIが作るので、CIの成果物でも起動確認を行う。

## 名称

製品名は「開闢（かいびゃく）」、用途を添えた表示は「開闢 — MDカード画像ツール」。`mdript` は開発コード、リポジトリ名、exe名として継続する。保存先の `%APPDATA%\mdript-v2` やTauriの識別子は、表示名とは別に保つ。
