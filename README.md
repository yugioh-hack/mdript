# Master Duel Scissors Scripts（愛称: mdript）

遊戯王 マスターデュエルのスクリーンショットからカードの部分を切り抜き、カード名を付けて保存する Windows 向けのツールです。カードのイラストを知覚ハッシュ (pHash) で照合して名前を決めます。

画像やフォルダをウィンドウにドロップするだけで使えます。FullHD、WQHD、4K、ウルトラワイドの画面を自動で判別するので、解像度を選ぶ必要はありません。判定に自信がない画像は `review/` フォルダに分けるため、確認なしに間違った名前で保存されることはありません。処理はすべて手元のPCで完結し、画像は外部に送信されません。カード名とマスター画像は同梱していません。必要なときに公式データベースから取得します。

非公式のファンツールです。株式会社KONAMIおよび遊戯王公式とは関係ありません。

---

## 特長

### 角丸のカード画像を出力できます

カードの四隅を実物と同じ角丸に切り抜き、角の外側を透明にして保存します。背景色のあるページや動画に貼っても、四隅に余白や黒い角が出ません。不要なら設定で切り替えられます。

### OCRを使わないので、高精度・高速で軽量です

カード名を文字認識で読む方式ではなく、イラストの特徴量（pHash）を同梱のデータと照合して名前を決めます。画面の文字の読み取り誤りに左右されません。実際のスクリーンショット約1万枚で試したところ、99.9%以上が確定し、誤った名前で保存されたものはありませんでした。ただしウィジャ盤など、イラストがほぼ同じカードは例外です（「既知の制限」を参照）。

OCR のモデルを動かす必要がないため、処理も速く済みます。1分間にスクリーンショット1,000枚以上を処理でき、1枚あたり約0.05秒です。

配布物も小さく収まります。OCR には PyTorch（2GB 超）が必要になりますが、このツールが使うのは Pillow と numpy だけです。exe は約 31MB の単一ファイルで、照合用のハッシュデータは約 650KB です。

## 使い方

### 1. スクリーンショットを撮る

マスターデュエルでカードの拡大表示を開き、全画面のままスクリーンショットを撮ります。拡大表示は、カード1枚が画面中央に大きく出る画面です。周りにウィンドウやメニューが写っていても処理できますが、ウィンドウモードで撮った画像は精度がやや下がります。

### 2. アプリを入手して起動する

[Releases](../../releases) から `mdript.exe` をダウンロードし、ダブルクリックで起動します。インストールも Python も不要です。

exe には署名がないため、初回起動時に Windows SmartScreen が警告を出すことがあります。その場合は「詳細情報」を押してから「実行」を選んでください。不安なときは、Releases にある `SHA256SUMS.txt` でファイルの改ざんを確かめるか、後述の方法でソースから実行できます。

### 3. カード名を取得する（初回のみ）

初回起動時に「カード名を取得しますか？」と表示されるので、［はい］を押してください。公式データベースからカード名を取得し、PCに保存します。約30秒かかります。

あとから取得する場合は、画面右上の［カードデータ更新…］から［カード名を取得］を選んでください。取得しなくても動作しますが、出力ファイル名が `cid_12345.webp` のようなカードIDになります。

### 4. スクリーンショットをドロップする

出力先を決めます。初期値は `ピクチャ\mdript` で、［変更］から別のフォルダを選べます。次に、スクリーンショットかそれを入れたフォルダを、ウィンドウの枠の中にドラッグ＆ドロップします。ドロップできない環境では、［ファイルを選ぶ］か［フォルダを選ぶ］を使ってください。

処理が終わると、一覧に結果が並び、出力先にカード画像が保存されます。［開く］を押すと出力先のフォルダが開きます。出力先をドロップしたフォルダの中に置いていても、前回の出力を再び処理することはありません。

### 出力先の構成

```
出力先/
├─ ブラック・マジシャン.webp      確定: カード名のファイル名で保存
├─ ブラック・マジシャン_alt1.webp  同名で別イラストのカード（連番が付く）
├─ review/                         要確認: 候補はあるが自信が足りないもの
├─ not_card/                       カードと判定できなかったもの（元のファイル名のまま）
└─ log.csv                         処理の記録（日時、状態、カード名、距離、元ファイル）
```

処理した画像が、保存されないまま消えることはありません。`review/` と `not_card/` は目で確認してください。

### 設定

設定は終了時に自動で保存されます。

| 設定 | 内容 |
| --- | --- |
| 解像度 | 通常は「自動」のままで問題ありません。拡大縮小された画像で外れる場合だけ、元の解像度を選びます |
| 形式 | `webp`（軽い）、`png`（劣化なし）、`both`（両方） |
| 角丸・透過 | カードの四隅を角丸にして透過させ、実物に近い見た目にします |
| サブフォルダも処理 | フォルダをドロップしたとき、中のフォルダも対象にします |
| 同じイラストは保存しない | 同じカードを保存済みなら、重複して保存しません |
| 要確認も保存する | `review/` への保存を行います |
| 判定できない画像も残す | `not_card/` への保存を行います |
| 英語版 | 英語クライアントで撮ったスクショの扱いです。「判別しない」（既定）、「英語名で保存」、「en に分ける」（日本語名のまま `en/` へ）、「英語名で en に分ける」から選びます（「英語クライアントのスクショ」を参照） |

### 新しいカードが出たとき

［カードデータ更新…］から［新しいカードセットを取り込む］を選ぶと、追加されたカードのイラストを公式データベースから取得し、照合できるようにします。80枚の新弾なら1つあたり約1分です（詳しくは「3. データの取得」）。取り込む前に処理した新カードは、`not_card/` に入ることがあります。

### コマンドラインで使う

大量の画像をまとめて処理するときは、コマンドラインが便利です。

```bash
python -m mdript スクショのフォルダ -o 出力先
```

| オプション | 内容 |
| --- | --- |
| `--format webp/png/both` | 出力形式（既定は webp） |
| `--quality 90` | WebP の画質 |
| `--no-rounded` | 角丸・透過にしない |
| `--no-recursive` | サブフォルダを見ない |
| `--keep-duplicates` | 同じイラストでも保存する |
| `--no-review` | 要確認の画像を保存しない |
| `--no-not-card` | 判定できなかった画像を保存しない |
| `--english off/name/folder/both` | 英語クライアントのスクショの扱い。`name` は英語名で保存、`folder` は `en/` に分ける、`both` は英語名で `en/` に分ける（既定は off） |
| `--resolution 1920x1080` | 元の解像度を指定する（拡大縮小された画像向け） |
| `--update-names` | 公式データベースからカード名を取得する |
| `--update-hashes` | 新しいカードセットを取り込む |
| `--learn カードID` | 画像1枚（カードの拡大画面）を、そのカードの照合用ハッシュとして追加する |

### ソースから実行する

Python 3.12 以降で動作を確認しています。必要なライブラリは Pillow と numpy だけです。`tkinterdnd2` はドラッグ＆ドロップ用で、入っていなければファイル選択ダイアログで動作します。

```bash
git clone <このリポジトリのURL>
cd mdript
pip install -r requirements.txt
python app.py
```

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| ほとんどが `not_card/` に入る | 全画面のカード拡大画面か確認してください。ウィンドウモードなら解像度を指定します。新カードなら「新しいカードセットを取り込む」を実行します |
| 特定のカードだけ `not_card/` に入る（カードの拡大画面なのに） | マスター画像と MD でイラストの切り方が違うカードです。`python -m mdript --learn カードID 画像.png` でその画像を照合用に追加すると、次から確定します（`%APPDATA%\mdript\card_hashes_user.json` に保存） |
| `review/` が多い | ウィンドウモードの画像は精度が下がります。全画面で撮り直すと確定しやすくなります |
| ファイル名が `cid_数字` になる | ［カードデータ更新…］から［カード名を取得］を実行してください |
| 「カード名を取得できませんでした」と出る | 公式サイトのメンテナンス中か、通信できていません。時間をおいて再実行してください |
| ドロップできない | tkdnd を読み込めない環境です。［ファイルを選ぶ］を使ってください |
| SmartScreen が警告を出す | 「2. アプリを入手して起動する」を参照してください |

### 既知の制限: ウィジャ盤と「死のメッセージ」

ウィジャ盤と死のメッセージ「E」「A」「T」「H」の5枚は、イラストがほぼ同じで、カード名の一部だけが違います。このツールはイラストだけで照合し、名前の文字は読まないため、5枚を正しく区別できません。

イラストの違いがごくわずかなため、確定の基準を満たしてしまい、別のカード名で「確定」として保存されることがあります。`review/` に回るとは限りません。

出力先に `ウィジャ盤` や `死のメッセージ` で始まるファイルがあれば、カードの名前を目で確かめ、必要ならファイル名を直してください。`log.csv` をカード名で検索すれば見つかります。これ以外のカードで、本物を別の名前で確定させた例は確認されていません（「検証結果」を参照）。

### プライバシーと通信

画像、ファイル名、フォルダ名を送信することはありません。通信が起きるのは、［カード名を取得］や［新しいカードセットを取り込む］を押したときだけです。送信先は公式データベース（`www.db.yugioh-card.com`）で、取得のリクエストしか送りません。アカウントやトラッキングはありません。

取得したデータと設定は `%APPDATA%\mdript\` に保存します。このフォルダを削除すれば初期状態に戻ります。公式データベースへのアクセスには0.4秒の間隔を空けます。通信は https に限り、別のサイトへのリダイレクトには従いません。

## 仕組み（技術的な詳細）

### 1. カード領域の決定

WQHD (2560x1440) で実測したカード枠 `(833, 69, 1727, 1371)` が基準です。
ゲームのUIは**画面の高さに比例して拡縮し、カードは水平方向の中央**に置かれるため、

```
倍率     = 画面の高さ / 1440
カード幅 = 894 × 倍率 、 カード高さ = 1302 × 倍率
左端     = 画面幅 / 2 − カード幅 / 2 、 上端 = 69 × 倍率
```

の1本の式で FullHD・WQHD・4K・ウルトラワイドすべてを扱えます
（基準枠の左右端 833 と 1727 の中点はちょうど画面中央の 1280 です）。

この枠で決まらなかった画像だけ、輪郭の強さからカード矩形を**検出**し、
さらに枠を少しずつ動かして最も一致する位置を探します
（ウィンドウモードのスクショや、切り抜き済みのカード画像への保険）。

### 2. 照合

カードのイラストを**2か所**ハッシュ化し、64bit×2 = **128bit** で照合します。

| 領域 | 範囲（カード画像に対する比率） | 理由 |
| --- | --- | --- |
| 上 | 18〜82% × **22〜38%** | マスター画像の SAMPLE 透かし（40〜48%）の上 |
| 下 | 18〜82% × **50〜62%** | 透かしの下に残っているイラスト |

1領域では透かしの上しか使えず情報が足りません。下側を足すと、
「要確認」が 19枚→3枚、カード以外の画像を誤って確定する割合が
**0.56%→0.00%** になりました（スクショ9,524枚・マスター14,753枚で実測）。

| 条件（128bitでの距離） | 判定 |
| --- | --- |
| 距離 ≤ 16 かつ 2位との差 ≥ 2 | 確定 |
| 距離 ≤ 32 かつ 2位との差 ≥ 4 | 確定 |
| 推定枠の場合は 距離 ≤ 16 かつ 差 ≥ 6 | 確定 |
| 距離 ≤ 36 | 要確認（`review/` へ） |
| それ以外 | カードなし（保存しない） |

しきい値の根拠は実測分布です。**本物のカードは正解までの距離が最大32**
（中央14・p99が24）、**カード以外の画像は最も近いカードでも34以上**
（4,000回試して32以下は0件）で、32と34の間できれいに分かれます。

枠を探している間だけは**上側64bitのみ**で採点します。
ビット数が多いほど切り出し位置のズレに弱くなるためで、
位置が決まってから128bit全体で確定を判断します。

OCR は使いません。実データ 18,504 件の処理ログでは 99.8% が画像照合だけで確定しており、
OCR のために PyTorch (2GB超) を抱える必要が無いためです。

### 3. データの取得

| データ | 同梱 | 取得方法 |
| --- | --- | --- |
| ハッシュ値 (`data/card_hashes.json`, 約650KB) | ○ | — |
| カード名・ルビ | × | ［カード名を取得］で公式DBから（約30秒 / 1.2MB） |
| マスター画像 | × | ［新しいカードセットを取り込む］で、必要な分だけ取得 |

取得したデータは `%APPDATA%\mdript\` に保存され、同梱データは書き換えません。

#### 新しいカードセットの取り込み

イラストが新しくなるのは新しいカードセットが出たときなので、更新もその単位で行います。

1. 収録シリーズの一覧を取得（1リクエスト・約0.4秒・1,520シリーズ）
2. 前回以降に増えたシリーズを洗い出す
3. ハッシュを持っていないカード（＝新カード）の画像を取得
4. 新しいシリーズに入っているカードは、**既存のカードでもイラストを取り直す**
   （新規イラストでの再録に追従するため。古いイラストのハッシュは消さずに足す）

初回は同梱ハッシュが全シリーズをカバーしている前提で、シリーズ一覧を
「取り込み済み」として記録するだけです（全14,000枚の取り直しは数時間かかるため）。

かかる時間の目安は、80枚の新弾1つで**約1分**（1枚ずつ0.4秒間隔で取得）。
新カードが無い再録のみのシリーズでも、シリーズが増えていれば取り直します。

#### 英語版にしか無いカード

TCG で先に出たカードや TCG だけの大会の賞品カードは、日本語版の公式DBにありません
（2026年10月時点で39枚）。カードIDは日本語版と英語版で共通で、マスターデュエルのイラストは
言語で変わらないので、英語クライアントのスクショも同じハッシュで照合できます。

* **ハッシュ値**: 同梱DBに入っています（英語版の公式DBの画像から作成）
* **カード名**: ［カード名を取得］で、日本語版の一覧に無いカードだけ英語版の一覧
  （`request_locale=en` の同じ検索）から英語名を補います。出力ファイル名は英語名になります。
  英語版の一覧の分だけ時間が延びます（合わせて約30秒）。英語版の一覧が取れなかったときは
  日本語版の分だけを保存します
* **新しいカード**: ［新しいカードセットを取り込む］では、英語名で補ったカードの画像を
  英語版のページから取ります。日本語版のページに画像が無いカードも英語版のページを試します。
  収録シリーズの確認（再録の取り直し）は日本語版の一覧だけで行います

日本語版でも発売されると、次の［カード名を取得］から日本語名になります（カードIDは同じなので、
ハッシュはそのまま使えます）。

#### 英語版で描き変えられたカード

英語版（TCG）では、銃火器・血液・性的描写などの規制のためにイラストが日本語版と少し違うカードがあります
（例: 「スキルドレイン」は日本語版の画像と距離 48 離れていて、英語クライアントのスクショが「カードなし」になっていました）。
どのカードが描き変えられているかは事前に分からないので、ygo の `en_images.py` で全カードの英語版の画像を取り、
`tools/build_hash_db.py --master-dir-en` で読みます。**同じカードの既存のハッシュとの距離が `--en-min-distance`（既定 12）以上のときだけ**
ハッシュを足し、ほとんど同じ絵でDBを膨らませません（`Catalog.add_hash` の `min_distance` と同じ考え方）。

* しきい値の根拠（取得済みの285枚で実測）: 既存のハッシュとの距離は 0〜3 が255枚、4〜11 が17枚と、同じ絵なら 11 以下に収まる。
  離れていたのは 12〜15 が3枚、20〜27 が2枚、40 以上が8枚（スキルドレインは 48）。
  確定の距離（16）より内側に取ると、描き変えのない画像のノイズを拾うので 12 にした
* 足したのは 285枚中13枚（4.6%）。同梱DBは 655,114 → 655,569 バイト（+455）。全カードで同じ割合なら +25KB 前後
* 英語クライアントのスクショ 101枚（`md_shots_en`）: スキルドレインが「カードなし（距離38）」→「確定（距離12）」になり、ほかの100枚は結果も距離も変わらない

### 4. 英語クライアントのスクショ

イラストは言語で変わらないため、英語クライアントのスクショも日本語版と同じカードに当たります。
設定の「英語版」を「判別しない」以外にすると、テキスト欄の文字が英語かどうかを見て、
英語なら英語名で保存したり `en/` に分けたりします（要確認の画像は `review/en/` に入ります）。

OCR は使わず、字の形で見分けます。漢字・かなは横画が多く、英字の小文字は縦画が多いので、
テキスト欄の文字のまわりで「上下方向の明るさの変化 ÷ 左右方向の変化」を測り、0.75 以下なら英語とします。

| | 比の範囲 |
| --- | --- |
| 日本語クライアント 4,139枚 | 最小 0.895（中央 1.18） |
| 英語クライアント 102枚 | 最大 0.612（中央 0.57） |

FullHD・1280x720 への縮小や JPEG 画質50 でも、日本語の最小値は 0.907 以上、英語の最大値は 0.672 以下で、
取り違えは1枚もありませんでした。英語の102枚には、通常モンスター・効果モンスター・ペンデュラム・
エクシーズ・魔法・罠が含まれます。文字が読み取れないときは日本語として扱います。

* **英語名**: ［カード名を取得］で英語版の一覧から取ります。このバージョンより前に取得したカード名には
  英語名が入っていないので、もう一度［カード名を取得］を実行してください。英語名が無いときは日本語名で保存し、
  備考に「英語名が未取得」と出ます
* 英語版にしか無いカード（「英語版にしか無いカード」を参照）は、日本語クライアントでもテキスト欄が英語なので、
  英語版として扱われます。カード名はもともと英語名です

## 検証結果

実際のスクリーンショット **9,526枚**（WQHD）での通し処理:

| | 1領域64bit | **2領域128bit（現行）** |
| --- | --- | --- |
| 確定 | 9,517 (99.91%) | **9,523 (99.97%)** |
| 要確認 | 9 | **1** |
| カードなし | 0 | 2 |
| エラー | 0 | 0 |
| 所要時間 | 437秒 | 471秒 (+8%) |

旧ツール（OCR併用）の判定と 9,523/9,524 (99.99%) が一致し、
**9,523件の「確定」の中に、誤った名前で保存されたものは 0件** です。

残った3枚の内訳:
* 要確認1枚 … 距離36・2位との差2で決め手に欠けたもの（名前は正解）
* カードなし2枚 … ゲーム内のイラストが公式DBのものと別物で、正解が候補に出ないもの
  （`not_card/` に元のファイル名で残るので、目視で拾えます）

解像度ごとの精度（同じ298枚を拡大縮小して検証）:

| 条件 | カード名の一致 | 確定率 |
| --- | --- | --- |
| WQHD 2560x1440（原本） | 298/298 | 100% |
| FullHD 1920x1080（縮小） | 298/298 | 100% |
| 4K 3840x2160（拡大） | 298/298 | 100% |
| FullHD + JPEG 画質50 | 298/298 | 100% |
| 1280x720 | 298/298 | 100% |
| ウルトラワイド 2560x1080 | 298/298 | 100% |
| 切り抜き済みカード画像 | 298/298 | 100% |

> **FullHD / 4K の検証について**
> 手元にネイティブの FullHD・4K スクリーンショットが無いため、WQHD の原本を
> 拡大縮小して検証しています。縮小は情報が落ちるぶん**本物の FullHD より不利な条件**、
> 拡大も同様にぼけるため**本物の 4K より不利な条件**であり、
> それでも 100% 一致したことから実機でも問題なく動く見込みです。
> ただし「UIが画面の高さに比例して拡縮し、カードが水平中央に来る」という前提だけは
> 実機のスクショでの確認をおすすめします（1枚あれば十分です）。

ウィンドウモードのスクショは枠の検出で救済していますが、精度は全画面より落ちます
（約82%が確定、残りは要確認）。全画面でのスクリーンショットを推奨します。

### カードではない画像を入れた場合

無関係な画像のハッシュが 14,732件のDBに対してどこまで近づくかを、
乱数ハッシュ4,000件で測った結果です。

| | 1領域64bit（旧） | **2領域128bit（現行）** |
| --- | --- | --- |
| 最小距離 | 8 | **34** |
| 確定の条件に入る割合 | 0.56% | **0.00%**（0/4,000） |

本物のカードは最大でも距離32なので、32と34の間で切れています。
カード以外の画像を「確定」として誤った名前で保存することは、
実測の範囲では起きません。

## 開発者向け

### テスト

```bash
python -m unittest discover -s tests -v
```

### exe を作る

```bash
pip install -r requirements.txt pyinstaller
pyinstaller mdript.spec
```

`dist/mdript.exe`（約31MB・単一ファイル）ができます。`requirements.txt` の依存を入れた Python で実行してください。入っていない環境でビルドすると、起動時に `No module named numpy` で止まる exe ができます。

`v1.0.0` のようなタグを push すると、GitHub Actions（`.github/workflows/build.yml`）で
テスト → exe ビルド → Releases への添付まで自動で行います。
main への push とプルリクエストではテストだけが走ります。

### 同梱ハッシュDBの作り直し

`tools/build_hash_db.py` でマスター画像から `data/card_hashes.json` を作ります
（マスター画像はリポジトリに含めません）。使い方はスクリプト冒頭のコメントを参照してください。

英語版にしか無いカードは、ygo の `en_cards.py` が作る `master_images_en/`（ファイル名がカードID）と
`json/yugioh_cards_en_only.json` を `--master-dir-en` / `--card-json-en` で読みます。
`--base data/card_hashes.json` を付けると、今の同梱DB（`--learn` で足したハッシュを含む）を消さずに足します。

```bash
python tools/build_hash_db.py --base data/card_hashes.json --master-dir-en ../YGO-list/master_images_en --card-json-en ../YGO-list/json/yugioh_cards_en_only.json
```

### 手元の切り抜き画像での回帰テスト

しきい値・ハッシュの領域・同梱ハッシュDBを変えたときは、リリース前に `tools/regress.py` を回します。
mdript が保存した切り抜き画像（ファイル名＝カード名）を正解データとして照合し、
結果を基準値 `tests/regress_baseline.json` と比べます。

```bash
python tools/regress.py --crops 切り抜きのフォルダ --screenshots
```

| オプション | 内容 |
| --- | --- |
| `--crops フォルダ` | 切り抜き画像のフォルダ（必須）。画像全体をカードとして照合する |
| `--screenshots` | フォルダ内の `log.csv` に残っている元のスクショ300枚も、原本・縮小・JPEG・ウィンドウ模擬の4通りで通す |
| `--update-baseline` | 今の結果を基準値として保存する |

次のどれかで失敗（終了コード 1）になります。

* 切り抜き画像に誤確定がある
* 基準値では確定していたカードが、確定しなくなった
* 元のスクショで誤確定が増えた、または確定率が1ポイントを超えて下がった

別のカードの名前で保存された画像と、同梱DBに足すべきカード（MD とマスター画像で
イラストの切り方が違うもの）も一覧に出ます。
画像とカード名はリポジトリに含めないので、このテストは GitHub Actions では走りません。
基準値に入っているのはカードIDと件数・距離だけです。
