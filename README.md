# Master Duel Scissors Scripts（愛称: mdript）

遊戯王 マスターデュエルのスクリーンショットからカードの部分だけを切り抜き、
イラストの知覚ハッシュ (pHash) で照合して **カード名を付けて保存** する Windows 向けのツールです。

* 画像やフォルダを**ドラッグ＆ドロップするだけ**（Python 不要の exe あり）
* **FullHD / WQHD / 4K / ウルトラワイド**に自動対応（解像度を選ぶ必要はありません）
* 判定に迷ったものは `review/` に分けるので、**黙って間違った名前で保存されない**
* **あなたの画像はどこにも送信されません**（処理はすべて手元のPCで完結します）
* カード名とマスター画像は同梱していません。必要なときにアプリから公式データベースで取得します

> 非公式のファンツールです。株式会社KONAMI および遊戯王公式とは無関係です。

## はじめかた（3ステップ）

### 0. 準備：スクリーンショットを撮る

マスターデュエルで**カードの拡大表示（カード1枚が画面中央に大きく出る画面）**を開き、
**全画面のままスクリーンショット**を撮ります。
カードの周りに余計なウィンドウやメニューが入っていても大丈夫ですが、
ウィンドウモードで撮ったものは判定の精度が少し落ちます（後述）。

### 1. アプリを入手して起動する

1. [Releases](../../releases) から `mdript.exe` をダウンロード
2. ダブルクリックで起動（インストール不要。Python も不要です）

> exe には署名をしていないため、初回起動時に Windows SmartScreen の警告
> （「WindowsによってPCが保護されました」）が出ることがあります。
> 「詳細情報」→「実行」を選んでください。
> 心配な場合は、Releases に添付している `SHA256SUMS.txt` でファイルが改ざんされていないか確認するか、
> 下記の[ソースから実行](#ソースから実行する)してください。

### 2. カード名を取得する（初回だけ）

初回起動時に「カード名を取得しますか？」と聞かれるので**［はい］**を押します（約20秒）。
公式データベースからカード名を取得して、お使いのPCに保存します。

* 後から行う場合は、画面右上の **［カードデータ更新…］ → ［カード名を取得］**
* 取得しなくても動きますが、ファイル名が `cid_12345.webp` のようなカードIDになります

### 3. スクリーンショットをドロップする

1. **出力先**を決める（初期値は `ピクチャ\mdript`。［変更］で好きなフォルダに）
2. スクリーンショット（またはスクショが入ったフォルダ）を、ウィンドウの枠の中に**ドラッグ＆ドロップ**
   （ドロップできない環境では、［ファイルを選ぶ］／［フォルダを選ぶ］を使います）
3. 一覧に結果が出て、出力先にカード画像が保存されます。［開く］で出力先を開けます

#### 出力先に作られるもの

```
出力先/
├─ ブラック・マジシャン.webp     … 確定：カード名のファイル名で保存
├─ ブラック・マジシャン_alt1.webp … 同名で別イラストのカード（連番が付く）
├─ review/                        … 要確認：候補はあるが自信が足りないもの
├─ not_card/                      … カードと判定できなかったもの（元のファイル名のまま）
└─ log.csv                        … 処理の記録（日時・状態・カード名・距離・元ファイル）
```

何も黙って捨てられることはありません。`review/` と `not_card/` は目視で確認してください。
出力先がドロップしたフォルダの中にあっても、前回の出力を処理し直すことはありません。

#### 設定の意味

| 設定 | 意味 |
| --- | --- |
| 解像度 | 通常は「自動」のままで OK。拡大縮小された画像で外れるときだけ元の解像度を選びます |
| 形式 | `webp`（軽い）/ `png`（劣化なし）/ `both`（両方） |
| 角丸・透過 | カードの四隅を角丸にして透過させる（実物に近い見た目） |
| サブフォルダも処理 | フォルダを丸ごとドロップしたとき、中のフォルダも見る |
| 同じイラストは保存しない | すでに同じカードを保存済みなら重複して保存しない |
| 要確認も保存する | `review/` への保存 |
| 判定できない画像も残す | `not_card/` への保存 |

設定は終了時に自動で保存されます。

### 新しいカードが出たとき

［カードデータ更新…］→**［新しいカードセットを取り込む］** を押すと、
追加されたカードのイラストを公式データベースから取得して照合できるようにします
（80枚の新弾1つで約1分。詳しくは下の「3. データの取得」）。
新カードを取り込む前のツールでは、新カードは `not_card/` に入ることがあります。

### コマンドラインで使う

大量の画像をまとめて処理したいときに便利です。

```bash
python -m mdript スクショのフォルダ -o 出力先
```

| オプション | 意味 |
| --- | --- |
| `--format webp/png/both` | 出力形式（既定 webp） |
| `--quality 90` | WebP の画質 |
| `--no-rounded` | 角丸・透過をしない |
| `--no-recursive` | サブフォルダを見ない |
| `--keep-duplicates` | 同じイラストでも保存する |
| `--no-review` | 要確認の画像を保存しない |
| `--no-not-card` | 判定できなかった画像を保存しない |
| `--resolution 1920x1080` | 元の解像度を指定（拡大縮小された画像向け） |
| `--update-names` | 公式DBからカード名を取得 |
| `--update-hashes` | 新しいカードセットを取り込む |

### ソースから実行する

Python 3.12 以降で動作確認しています。

```bash
git clone <このリポジトリのURL>
cd mdript
pip install -r requirements.txt
python app.py
```

必要なのは **Pillow と numpy だけ**です（`tkinterdnd2` はドラッグ＆ドロップ用で、
無い場合はファイル選択ダイアログで動きます）。

### うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| ほとんど `not_card/` に入る | 全画面のカード拡大画面か確認。ウィンドウモードなら解像度を指定。新カードなら「新しいカードセットを取り込む」 |
| `review/` が多い | ウィンドウモードのスクショは精度が落ちます。全画面で撮り直すと確定になりやすいです |
| ファイル名が `cid_数字` | ［カードデータ更新…］→［カード名を取得］を実行 |
| 「カード名を取得できませんでした」 | 公式サイトがメンテナンス中か、通信できていません。時間をおいて再実行 |
| ドロップできない | tkdnd が読めない環境です。［ファイルを選ぶ］を使ってください |
| SmartScreen の警告 | 上の「アプリを入手して起動する」を参照 |

### 既知の制限：ウィジャ盤と「死のメッセージ」

次の5枚は、イラストがほぼ同じで、カード名の一部だけが違います。

* ウィジャ盤
* 死のメッセージ「E」「A」「T」「H」

このツールはイラストだけで照合し、名前の文字までは読まないので、**これらのカードは正しく見分けられません**。
同梱ハッシュ上でも、5枚のうち4組はイラストの差がごくわずか（ウィジャ盤と「E」は2bit）で、
確定の基準（差が小さくてもよい範囲）に入ってしまいます。そのため、

* **別のカード名で「確定」として保存されることがあります**（`review/` に回るとは限りません）
* 同じイラストのカードは、ファイル名が `_alt1` のような連番になることもあります

出力先に `ウィジャ盤*` や `死のメッセージ*` のファイルがあったら、**カードの名前を目で見て確認し、
必要ならファイル名を直してください**。`log.csv` のカード名で検索すると拾えます。
他のカードでは、本物のカードを別のカード名で確定させた例は確認されていません（下記の検証結果を参照）。

### プライバシーと通信

* 画像・ファイル名・フォルダ名は**一切送信しません**。通信するのは、あなたが
  ［カード名を取得］／［新しいカードセットを取り込む］を押したときの、公式データベース
  （`www.db.yugioh-card.com`）への取得リクエストだけです。アカウントやトラッキングはありません。
* 取得したデータと設定は `%APPDATA%\mdript\` に保存されます（削除すれば初期状態に戻ります）。
* 公式データベースには 0.4 秒間隔でアクセスします。通信先は公式サイトの https のみで、
  別のサイトへのリダイレクトは辿りません。

## 仕組み（技術的な詳細）

### 1. カード領域の決定

WQHD (2560x1440) で実測したカード枠 `(833, 69, 1727, 1371)` が基準です。
ゲームのUIは**画面の高さに比例して拡縮し、カードは水平方向の中央**に置かれるため、

```
倍率     = 画面の高さ / 1440
カード幅 = 894 × 倍率 、 カード高さ = 1302 × 倍率
左端     = 画面幅 / 2 − カード幅 / 2 、 上端 = 69 × 倍率
```

の1本の式で FullHD・WQHD・4K・ウルトラワイドすべてを扱えます
（基準枠の左右端 833 と 1727 の中点はちょうど画面中央の 1280 です）。

この枠で決まらなかった画像だけ、輪郭の強さからカード矩形を**検出**し、
さらに枠を少しずつ動かして最も一致する位置を探します
（ウィンドウモードのスクショや、切り抜き済みのカード画像への保険）。

### 2. 照合

カードのイラストを**2か所**ハッシュ化し、64bit×2 = **128bit** で照合します。

| 領域 | 範囲（カード画像に対する比率） | 理由 |
| --- | --- | --- |
| 上 | 18〜82% × **22〜38%** | マスター画像の SAMPLE 透かし（40〜48%）の上 |
| 下 | 18〜82% × **50〜62%** | 透かしの下に残っているイラスト |

1領域では透かしの上しか使えず情報が足りません。下側を足すと、
「要確認」が 19枚→3枚、カード以外の画像を誤って確定する割合が
**0.56%→0.00%** になりました（スクショ9,524枚・マスター14,753枚で実測）。

| 条件（128bitでの距離） | 判定 |
| --- | --- |
| 距離 ≤ 16 かつ 2位との差 ≥ 2 | 確定 |
| 距離 ≤ 32 かつ 2位との差 ≥ 4 | 確定 |
| 推定枠の場合は 距離 ≤ 16 かつ 差 ≥ 6 | 確定 |
| 距離 ≤ 36 | 要確認（`review/` へ） |
| それ以外 | カードなし（保存しない） |

しきい値の根拠は実測分布です。**本物のカードは正解までの距離が最大32**
（中央14・p99が24）、**カード以外の画像は最も近いカードでも34以上**
（4,000回試して32以下は0件）で、32と34の間できれいに分かれます。

枠を探している間だけは**上側64bitのみ**で採点します。
ビット数が多いほど切り出し位置のズレに弱くなるためで、
位置が決まってから128bit全体で確定を判断します。

OCR は使いません。実データ 18,504 件の処理ログでは 99.8% が画像照合だけで確定しており、
OCR のために PyTorch (2GB超) を抱える必要が無いためです。

### 3. データの取得

| データ | 同梱 | 取得方法 |
| --- | --- | --- |
| ハッシュ値 (`data/card_hashes.json`, 約650KB) | ○ | — |
| カード名・ルビ | × | ［カード名を取得］で公式DBから（約20秒 / 1.2MB） |
| マスター画像 | × | ［新しいカードセットを取り込む］で、必要な分だけ取得 |

取得したデータは `%APPDATA%\mdript\` に保存され、同梱データは書き換えません。

#### 新しいカードセットの取り込み

イラストが新しくなるのは新しいカードセットが出たときなので、更新もその単位で行います。

1. 収録シリーズの一覧を取得（1リクエスト・約0.4秒・1,520シリーズ）
2. 前回以降に増えたシリーズを洗い出す
3. ハッシュを持っていないカード（＝新カード）の画像を取得
4. 新しいシリーズに入っているカードは、**既存のカードでもイラストを取り直す**
   （新規イラストでの再録に追従するため。古いイラストのハッシュは消さずに足す）

初回は同梱ハッシュが全シリーズをカバーしている前提で、シリーズ一覧を
「取り込み済み」として記録するだけです（全14,000枚の取り直しは数時間かかるため）。

かかる時間の目安は、80枚の新弾1つで**約1分**（1枚ずつ0.4秒間隔で取得）。
新カードが無い再録のみのシリーズでも、シリーズが増えていれば取り直します。

## 検証結果

実際のスクリーンショット **9,526枚**（WQHD）での通し処理:

| | 1領域64bit | **2領域128bit（現行）** |
| --- | --- | --- |
| 確定 | 9,517 (99.91%) | **9,523 (99.97%)** |
| 要確認 | 9 | **1** |
| カードなし | 0 | 2 |
| エラー | 0 | 0 |
| 所要時間 | 437秒 | 471秒 (+8%) |

旧ツール（OCR併用）の判定と 9,523/9,524 (99.99%) が一致し、
**9,523件の「確定」の中に、誤った名前で保存されたものは 0件** です。

残った3枚の内訳:
* 要確認1枚 … 距離36・2位との差2で決め手に欠けたもの（名前は正解）
* カードなし2枚 … ゲーム内のイラストが公式DBのものと別物で、正解が候補に出ないもの
  （`not_card/` に元のファイル名で残るので、目視で拾えます）

解像度ごとの精度（同じ298枚を拡大縮小して検証）:

| 条件 | カード名の一致 | 確定率 |
| --- | --- | --- |
| WQHD 2560x1440（原本） | 298/298 | 100% |
| FullHD 1920x1080（縮小） | 298/298 | 100% |
| 4K 3840x2160（拡大） | 298/298 | 100% |
| FullHD + JPEG 画質50 | 298/298 | 100% |
| 1280x720 | 298/298 | 100% |
| ウルトラワイド 2560x1080 | 298/298 | 100% |
| 切り抜き済みカード画像 | 298/298 | 100% |

> **FullHD / 4K の検証について**
> 手元にネイティブの FullHD・4K スクリーンショットが無いため、WQHD の原本を
> 拡大縮小して検証しています。縮小は情報が落ちるぶん**本物の FullHD より不利な条件**、
> 拡大も同様にぼけるため**本物の 4K より不利な条件**であり、
> それでも 100% 一致したことから実機でも問題なく動く見込みです。
> ただし「UIが画面の高さに比例して拡縮し、カードが水平中央に来る」という前提だけは
> 実機のスクショでの確認をおすすめします（1枚あれば十分です）。

ウィンドウモードのスクショは枠の検出で救済していますが、精度は全画面より落ちます
（約82%が確定、残りは要確認）。全画面でのスクリーンショットを推奨します。

### カードではない画像を入れた場合

無関係な画像のハッシュが 14,732件のDBに対してどこまで近づくかを、
乱数ハッシュ4,000件で測った結果です。

| | 1領域64bit（旧） | **2領域128bit（現行）** |
| --- | --- | --- |
| 最小距離 | 8 | **34** |
| 確定の条件に入る割合 | 0.56% | **0.00%**（0/4,000） |

本物のカードは最大でも距離32なので、32と34の間で切れています。
カード以外の画像を「確定」として誤った名前で保存することは、
実測の範囲では起きません。

## 開発者向け

### テスト

```bash
python -m unittest discover -s tests -v
```

### exe を作る

```bash
pip install pyinstaller
pyinstaller mdript.spec
```

`dist/mdript.exe`（約31MB・単一ファイル）ができます。

`v1.0.0` のようなタグを push すると、GitHub Actions（`.github/workflows/build.yml`）で
テスト → exe ビルド → Releases への添付まで自動で行います。
main への push とプルリクエストではテストだけが走ります。

### 同梱ハッシュDBの作り直し

`tools/build_hash_db.py` でマスター画像から `data/card_hashes.json` を作ります
（マスター画像はリポジトリに含めません）。使い方はスクリプト冒頭のコメントを参照してください。
